# LZHA

LZHA — небольшой экспериментальный архиватор без потерь, написанный на C++. Он использует поиск совпадений в стиле LZ77, затем кодирует результат алгоритмом Хаффмана и сохраняет архивы в собственном формате `.lzha`.

Проект сделан для изучения и экспериментов. С обычными файлами он работает, но текущая реализация не рассчитана на большие входы и production-использование.

[English version](README.md)

## Сборка

Исходник требует C++17 или новее. Нативная сборка на macOS или Linux:

```bash
clang++ -std=c++20 -O2 -Wall -Wextra -pedantic lzha.cpp -o lzha
```

Сборка Windows PE на macOS через MinGW-w64:

```bash
x86_64-w64-mingw32-g++ -std=c++20 -O2 -static -static-libgcc -static-libstdc++ lzha.cpp -o lzha.exe
```

## Использование

```text
lzha [compress|decompress] <input> <output>
```

Сжать файл:

```bash
./lzha compress input.bin output.lzha
```

Распаковать архив:

```bash
./lzha decompress output.lzha restored.bin
```

Программа не определяет операцию по расширению файла. Режим нужно указывать явно.

## Реализация

У архиватора два этапа:

1. LZ77 заменяет повторяющиеся последовательности парами `(offset, length)`.
2. Хаффман кодирует литералы и символы длин совпадений в битовый поток.

Текущие параметры LZ77:

| Параметр | Значение |
|---|---:|
| Окно поиска | 4096 байт |
| Минимальная длина совпадения | 3 байта |
| Максимальная длина совпадения | 258 байт |
| Лимит цепочки кандидатов | 64 |
| Смещение совпадения | 12 бит |

Архив начинается с magic `LZHA`, байта версии и таблицы частот, по которой распаковщик восстанавливает дерево Хаффмана. После заголовка идёт закодированный битовый поток с маркером конца.

Ниже приведено локальное сравнение размеров на macOS ARM64. Размеры указаны в байтах. Для ZIP использовалась системная утилита `zip`. Это не benchmark скорости.

| Файл | Исходник | ZIP | LZHA | Процент сжатия (ZIP / LZHA) |

На этих входных данных LZHA создаёт архивы больше ZIP. Улучшение степени сжатия — одна из следующих задач проекта.

## Проверка

Базовая проверка корректности — round trip с последующим побайтовым сравнением:

```bash
./lzha compress path/to/input.txt /tmp/input.lzha
./lzha decompress /tmp/input.lzha /tmp/input.restored
cmp path/to/input.txt /tmp/input.restored
```

Такая проверка выполнена локально для `warandpeace.txt`, `rockyou.txt` и небольших бинарных файлов. Benchmark-датасеты не входят в публичный репозиторий.

## Ограничения

Сейчас архиватор загружает весь исходный файл в память. Поиск LZ77 также создаёт `prev` с одним `int` на каждый байт входного файла. Поток токенов и закодированный битовый поток одновременно остаются в памяти.

Для файла `HDFS.log` размером 1,58 GB один только `prev` занимает около 6,31 GB (5,88 GiB). Наблюдавшийся пик во время сжатия составил примерно 9,5 GB. При распаковке весь результат собирается в памяти до записи на диск.

Планируемое решение — обработка блоками или потоками с ограниченным скользящим окном. Это потребует более серьёзной переработки: поиск должен работать через границы блоков, метаданные Хаффмана нельзя завязывать на хранение всего потока токенов, а декодер должен сохранять историю окна. Это не небольшое локальное изменение текущего кода.

Другие ограничения:

- Пустые входные файлы не поддерживаются.
- В архиве нет checksum.
- Проверка повреждённых архивов ограничена.
- Целочисленные поля используют byte order текущей платформы.
- Автоматических тестов и CI пока нет.

## Структура репозитория

```text
lzha.cpp       # реализация и CLI
README.md      # документация на английском
README.ru.md   # документация на русском
benchmarks/    # скриншоты измерений
```

Большие benchmark-файлы хранятся локально и намеренно не загружаются в публичный репозиторий. GitHub отклоняет отдельные файлы больше 100 MB, а `rockyou.txt` является известным слитым списком паролей. Скриншотов и измерений достаточно, чтобы показать результаты без распространения самих датасетов.
